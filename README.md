# PHI-SPIKE — Cessna 172 (Re-trimmed)

## What this is

This repo trains and evaluates PHI-SPIKE — a physics-informed spiking
neural network for aircraft fault diagnosis — on a JSBSim-simulated
Cessna 172, using the corrected simulation and training pipeline.

## What we used it for

This repo exists to answer a methodology-integrity question, not a
new research question. The **original** Cessna 172 campaign (5
variants × 5 seeds, ~7 days of compute) was generated by an earlier
version of the simulator — one that never called JSBSim's trim
solver. That earlier simulator produced telemetry that stayed in a
survivable flight regime without ever reaching true force/moment
equilibrium: not obviously invalid, but generated by a looser physical
guarantee than the pipeline used everywhere else in this project.

Rather than assume that mattered, this repo **re-runs the identical
5-variant × 5-seed campaign on the identical airframe**, changing only
the simulation/training pipeline (trim fix, LIF shape fix, membrane
clamp, gradient value-clip — see below), so the original and re-trimmed
results can be directly compared.

**What this comparison is for**: the PHI-SPIKE project separately
tests generalization across airframes (Cessna 182, PA-28). That
comparison is only clean if every airframe uses the same methodology.
This repo's job is to confirm — or correct — whether the original
Cessna 172 baseline is safe to compare against those other airframes as-is,
or whether it needs to be replaced by this re-trimmed version first.

Same 5-variant ablation, same 10-class fault taxonomy as the rest of
the project — see the Cessna 182 repo for the full research framing.
This repo is about pipeline integrity, not new methodology.

## Verified trim envelope

Wide range (see `datasets/factory.py::ENVELOPES`, `c172x` entry) — the
original tuning target for the dataset generator's default envelope,
carried over unchanged by this fix pass.

```bash
python -m training.train_campaign \
```

Real campaign — note the distinct save directory, to avoid overwriting

```bash
python -m training.train_campaign \
  --epochs 40 --batch-size 32 --device cpu --seeds 0,1,2,3,4 \
  --variants vanilla_snn,snn_physics_loss,snn_membrane_conditioning,snn_temporal_physics,full_phi_spike \
  --n-clean 40 --sequence-len 80 --aircraft c172x \
  --save-dir experiments/full_campaign/c172x_retrim
```
Launch with `nohup ... &; disown`, not `tmux`.

## What changed since the original campaign

1. **JSBSim trim.** The original simulator never called `do_trim()` at
   all — it set initial conditions and applied small control
   perturbations without ever reaching force/moment equilibrium. Fixed
   with `propulsion/set-running = -1` (not
   `propulsion/engine/set-running`, which silently no-ops) + `do_trim(1)`.

2. **Trim-relative control.** Even with trim working, naively applying
   raw control deltas (instead of trim-value + delta) discards the
   trim solution on the first control input. Fixed.

3. **LIF layer shape bug.** An auto-transpose heuristic in
   `LIFLayer.forward()` silently scrambled batch and time dimensions
   on nearly every real batch. Removed.

4. **Membrane potential clamp.** Neither LIF class bounded its
   internal state, risking numerical overflow at full training scale.
   Fixed with `torch.clamp(..., -50.0, 50.0)`.

5. **Gradient value-clipping.** Norm-clipping alone was insufficient —
   raw gradients were observed reaching into the trillions before
   clipping. Added `clip_grad_value_(..., 5.0)`.

All five fixes were found and verified on the Cessna 182 repo first,
then ported here.

## Interpreting a comparison against the original campaign

If the ablation *pattern* (e.g. `full_phi_spike` beating
`snn_physics_loss` by roughly the same margin) replicates between the
original and re-trimmed runs, that's evidence the original c172x
baseline was not meaningfully distorted by the missing trim step, and
can reasonably continue to serve as the project's reference baseline.

If the pattern differs meaningfully, the original campaign should be
treated as superseded by this one for any cross-airframe comparison —
report the re-trimmed numbers, and note the discrepancy explicitly
rather than silently swapping which number gets cited.

## Before you trust any result from this repo

- Run the 3-epoch smoke test first. `[skipped N non-finite batches]`
  should read `0`. If it climbs epoch over epoch, stop.
- Full scale (`n_clean=40`) is memory-heavy — confirmed to OOM-kill a
  <8GB box during development. Check `free -h` partway through a real
  run.
- Use `nohup ... &; disown` for long runs, not `tmux`.

## Repository structure

```
simulation/       JSBSim aircraft wrapper, trim, telemetry generation
fault_injection/  10-class fault taxonomy, randomized onset/severity injection
physics/          Physics-consistency residual computation
encoding/         Telemetry -> spike encoding
models/
  vanilla_snn/    Baseline LIF network (no physics coupling)
  phi_spike/      Physics-conditioned LIF + the 4 physics-aware variants
datasets/         Dataset assembly, envelope config, windowing
training/         train_campaign.py -- main entry point
baselines/        Non-spiking comparison models
robustness/       Noise/dropout/severity robustness sweeps
edge_emulation/   Streaming inference latency benchmarks
evaluation/       Metrics aggregation, figures
verification/     Pipeline sanity checks
dashboard/        Results visualization server
```
